# Open DFX vs Vivado DFX (7-series): feature matrix

This doc is the working checklist for the user's bar: "as close as you can get to Vivado DFX without testing" (2026-11-05).

**Status values:**
- **done:** verified by run, with evidence linked.
- **partial:** some of it works, and the gap is stated.
- **todo:** not started.
- **n/a:** does not apply to 7-series.

"Vivado reference" means a Vivado 2025.2 build we analysed with flow/bitparse.py. It does not mean Xilinx documentation unless a UG is cited.

## Independent verification of our outputs (beyond what Vivado offers)
- byteman applies each partial; the result equals the original target in all 5408 frames (flow/byteman_check.sh).
- region2v: region bits → netlist from prjxray-db only, plus simulation and a SAT proof against the RTL (flow/region2v.py).
- fasm2bels: whole bitstream → netlist, plus the firmware test (flow/bit2netlist.sh).
- Gate-level firmware simulation of the netlists (flow/gl_sim.sh).

## Pass-1 note (phase 10)
- Vivado's rule: pass 1 keeps exactly the static checkpoint's pips (static routing up to the partition pins). It holds back all other region INT pips, the DSP tie-offs, and the HCLK leaf pips of the region's columns.
- This explains all of phase 9's 23–29 words except the DSP `AREG_1`/`BREG_1` bits (docs/phase10 §4).
- Round 2 (docs/phase10 §9) adds two more rules, both opt-in.
  - Vivado also holds back DSP48E1 `AREG_1`/`BREG_1`, i.e. AREG=1/BREG=1 only: 13/13 and 13/13 cells; never AREG/BREG 0 or 2, 0/9 each.
  - It also holds back CARRY4 `PRECYINIT.CIN` (17/17), but not `AX`/`C1`.
  - Why Vivado holds back the DSP bits is not known.
- Vivado's compressed partials imply that the last frame of an FDRI write is not committed (a zero flush frame lands on an already written, non-zero frame). bitparse `--strict` models this, and every `--simulate` now checks both models.
