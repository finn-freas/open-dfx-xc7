# nextpnr-gt-unisim-defaults (draft, not posted)

Base: the ofx 0.1 nextpnr series (install/patches/nextpnr 0001-0027) plus nextpnr-partition-pins-ce-sr; applies to
`himbaechel/uarch/xilinx` only (xilinx.cc option, fasm.cc, new generated header gt_unisim_defaults.h).
Opt-in: `-o gt-unisim-defaults`. Off, the FASM is unchanged.

## Problem (docs/gtp.md section 2)
yosys writes only the parameters an instance sets. For every other GTPE2_CHANNEL, GTPE2_COMMON and PCIE_2_1
parameter nextpnr's FASM writer uses its own default, and 120 of them differ from UNISIM:
- PCIE_2_1 `PL_FAST_TRAIN` TRUE (simulation-only LTSSM timers) and `AER_CAP_VERSION` 1;
- GTPE2_COMMON `PLL0/1_FBDIV` 1 vs 4, `PLL0/1_FBDIV_45` 4 vs 5;
- 114 GTPE2_CHANNEL parameters, e.g. `CHAN_BOND_MAX_SKEW` 0 (out of range: nextpnr stops with "CHAN_BOND_MAX_SKEW
  may only range from 1 to 14, but is: 0"), `RX_DATA_WIDTH` 0, `PMA_RSV` 0.
The PCIE_2_1 `SPARE_BIT0..8`, `SPARE_BYTE0..3`, `SPARE_WORD0..3` attributes have bits in prjxray-db but were never
written, so a set value was lost silently.

The flow works around it in `flow/gt_json_defaults.py` (fills the netlist before nextpnr).

## Change
- `gt_unisim_defaults.h`: the UNISIM default of all 554 GTPE2_CHANNEL / GTPE2_COMMON / PCIE_2_1 parameters in yosys'
  JSON encoding, generated by `flow/gt_unisim_header.py` from yosys' `techlibs/xilinx/cells_xtra.v` (the same table
  gt_json_defaults.py uses).
- With the option, `write_ip` fills each missing parameter of such a cell with `Property::from_string(default)`
  before calling the cell's writer, and restores the cell's parameters afterwards (the routed JSON is unchanged).
- With the option, `write_pcie_2_1` writes the SPARE_* attributes (`SPARE_BIT<n>[0:0]`, `SPARE_BYTE<n>[7:0]`,
  `SPARE_WORD<n>[31:0]`).

## Evidence (2026-11-08, `flow/gt_unisim_check.sh`, outputs ~/ofx-test/fixes/gt)
Sparse sources (only the rate attributes / PL_FAST_TRAIN set), synthesized without gt_json_defaults.py:

| design | draft: unfilled netlist + `-o gt-unisim-defaults` vs workaround: filled netlist, option off | unfilled netlist, option off (the bug) |
|---|---|---|
| pcie_bare (PCIE_2_1) | PASS: FASM same apart from 17 SPARE_* lines (all zero), `.frames` identical | 1 FASM line differs: AER_CAP_VERSION 1 instead of 2 (this source sets PL_FAST_TRAIN itself) |
| gtp_lbm (GTPE2_CHANNEL/COMMON) | PASS: FASM identical, `.frames` identical | does not build: CHAN_BOND_MAX_SKEW 0 |
| blinky (no GT) | FASM identical with and without the option | |

So the draft reproduces the flow workaround bit for bit. The workaround's own equivalence to Vivado-filled
sources is in docs/gtp.md section 4; pcie_bare at defaults equals Vivado in the PCIe tiles (section 3).

Not covered: GTXE2 (Kintex-7) cells keep the writer defaults; the `IS_*_INVERTED` and `SIM_*` parameters the writer
never reads have no bits in the database.
