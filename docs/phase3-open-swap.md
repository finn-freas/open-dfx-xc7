# Phase 3: open-tools region swap (built and checked offline; not yet on hardware)

No Vivado is used in this flow. The tools are Yosys 0.70+186, openXC7 nextpnr-xilinx ce3f7c18, prjxray a5589d51 and prjxray-db a8b09269.

## Flow (flow/build_pr.py, DRY_RUN by default; add --run)
1. Synthesize the static design once: designs/pr_open/top.v plus rm_stub.v, where rm_slot is a (* blackbox *).
   - Yosys auto names depend on the whole netlist. A static design synthesized together with each RM got different names in each build, so replay of RM-B against RM-A's placement failed with "Bel ... is not valid for cell".
2. Synthesize each RM out of context: rm_shell.v plus rm_core_<x>.v, with `-noiopad -noclkbuf`.
3. Link without re-optimising:
   `read_json static; delete =A:blackbox; read_json rm; delete =A:blackbox; read_verilog -lib +/xilinx/cells_sim.v +/xilinx/cells_xtra.v; hierarchy; flatten; write_json -selected`.
4. The RM shell (flow/gen_shell.py) has every cell pinned with a BEL attribute in nextpnr's own naming, X<grid_x>Y<grid_y>/SLICE_X<i>Y0.<bel>:
   - 8 input anchors (LUT1 pass-through) and 4 output FFs, at the same bels in every RM, so boundary routes are identical;
   - core logic pinned inside the region;
   - 98 input-less LUT1 blockers, one in every region tile that has no other pinned cell.
   - All shell cells are listed in `-o preplaced`, so nextpnr closes those 100 tiles to cells without a BEL (xilinx_place.cc:666).
   - Without blockers, nextpnr placed the whole static counter inside the region.
   - With blockers that took an input net, the router used INT_L_X12 and INT_R_X9 to reach them, which changed static frames.
5. Build configuration A with the RM pins only. Then dump A's static cells and nets (flow/replay_dump.py, which converts the output names back to nextpnr's input names).
6. Build configuration B with `-o preplaced` (A's static cells plus B's RM pins) and `-o prerouted` (A's static nets, including u_rm.clk, u_rm.din[*] and u_rm.dout[*]).

## Results (verified by run)
- Self-replay of blinky gives bit-identical frames: 91 cells and 128 nets replayed, 0 collided.
- pr_open A (count) and B (shift):
  - B: 209 cells pinned, 136 static nets replayed, 0 collided, Fmax 391 MHz against a 100 MHz target.
  - flow/pr_check.py: 16 frames differ, all inside the region, 0 outside. Region frames carry no changed words of outside tiles. ECC is valid in all non-zero frames of both bitstreams.
- Partial bitstreams (flow/partial.py, with Vivado's packet layout and two passes): build/partials/pr_open/rm_*_from_*.bit (flow/make_partials.sh).
  - 59,272 bytes of data.
  - Pass 1 holds back 10 RM pips (shift) and 4 (count), and keeps the 25 static pips that lie in the region.
  - Gate: every frame written is a region frame, except one run-end pad frame, which carries the full bitstream's own content.
  - CRC verified.
  - Simulated load: full A + partial(B) equals full B frame for frame, and B + partial(A) equals A.

## Preferred hardware path: the FPGA loads its own partial through ICAPE2 (designs/pr_uart)
- Static design: the counter and LEDs, plus uart_icap.v.
  - UART: 1 Mbaud on A9/D10. Pins are from Digilent's Arty-A7-35-Master.xdc.
  - Protocol:
    - 'W' + N (4 bytes) + N big-endian words: the words go to ICAPE2 with the bits of each byte reversed (SWAP=1). The device answers 'K' + N.
    - 'R' + N: N ICAP reads, returned as words.
  - Simulated with iverilog (designs/pr_uart/tb): writes, acks and reads pass.
  - The ICAP byte bit-swap follows the usual Xilinx convention and is not yet verified on silicon. The IDCODE readback below tests it.
- Open PR build (flow/build_pr.py --design pr_uart --run):
  - 983 static nets replayed, 0 collided;
  - A vs B: 15 frames differ, all inside the region, static identical outside;
  - Fmax 210 MHz against a 100 MHz target.
- Partials: build/partials/pr_uart/rm_*_from_*.bin (regenerated by flow/make_partials.sh from the region-confined _c builds). Each comes with a .check.json safety record (sha256, region, simulated load). host/icap_load.ps1 refuses to send a file whose record is missing, mismatched, or not simulated clean. That refusal was tested with a 1-bit-tampered copy.
- Steps:
  1. Load the full bitstream with the stock loader:
     `openFPGALoader -b arty_a7_35t build/openxc7/pr_uart/pr_count_c/top_icapbits.bit`
     Load top_icapbits.bit FIRST: it is top.bit plus the 3 CFG_CENTER_MID bits Vivado always sets with ICAPE2 (docs/drafts/prjxray-db-icap-bits.md), so it matches Vivado's output.
     flow/icap_variant.sh made it and verified it differs from top.bit in exactly those 3 bits. Partials apply to it unchanged (simulated). Fall back to top.bit only for comparison.
  2. Read the IDCODE through ICAP (on Windows; COMx is the Arty's USB serial port):
     `powershell -File host\icap_load.ps1 -ReadIdcode -Run -Port COMx`
     Expected: "IDCODE 0x0362D093 seen". If it is not seen, the bit-swap or ICAP bit hypotheses are wrong. Do not continue to step 3.
  3. Swap the module:
     `powershell -File host\icap_load.ps1 -Partial build\partials\pr_uart\rm_shift_from_count.bin -Run -Port COMx`
     Expected: the LEDs change from counting to a walking one.
  4. Swap back with rm_count_from_shift.bin.

## Hardware test over JTAG (alternative). Exact steps once an Arty A7-35T is connected
Safety first:
- Watch board current with a USB power meter during every load, and unplug at once if it jumps.
- Load only partials that flow/partial.py wrote; its gate refuses anything else.
- The region is 2 CLB columns x 50 rows.

1. Load the full static plus RM A design, the normal way. Expected result: LEDs show the counter's top bits.
   `toolchain/oss-cad-suite/bin/openFPGALoader -b arty_a7_35t build/openxc7/pr_open/pr_count_c/top.bit`
2. Load the partial. openFPGALoader v1.2.0 cannot do this: it always sends JPROGRAM (src/xilinx.cpp:978), which wipes the device.
   - The draft patch adds `--partial`, which skips JPROGRAM and JSTART (docs/drafts/openfpgaloader-partial.md).
   - It is not built: this machine lacks cmake, pkg-config and libftdi headers.
   - With a patched build: `openFPGALoader -b arty_a7_35t --partial build/partials/pr_open/rm_shift_from_count.bit`
   - Expected result: the LEDs switch from counting to a walking one, and the counter keeps running.
3. Swap back with open_count.bit.

## Known limits
- Placement confinement is done with the pinned shell and blockers, not a general region constraint. docs/drafts/nextpnr-pblock-xdc.md is an uncompiled draft for real pblock support.
- Routing is not confined. The safety net is pr_check.py: build B's static frames must equal A's outside the region, and the build is rejected otherwise. Router confinement is Phase 4.
- Only one region shape and one column type (CLB) have been exercised.
