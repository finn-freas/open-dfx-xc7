# DRAFT issue (not posted): bits Vivado 2025.2 sets that prjxray-db a8b09269 does not decode (xc7a35t)

Target repo: openXC7/prjxray-db or f4pga/prjxray-db. Posting needs the user's approval. Nothing here was tested on hardware.

## Method
- Part xc7a35tcsg324-1 (fabric xc7a50t). prjxray-db a8b09269. Vivado v2025.2, SW Build 6299465 (ML Standard).
- One tiny design per primitive, generated by flow/gap_designs.py into designs/gap/<name>/.
- Vivado: vivado/build_gap.tcl via vivado/run_gap.ps1 (non-project; synth, opt, place, route, write_bitstream).
- Decode: flow/bit2fasm.py --verbose (prjxray bitread + bits_to_fasm). An unknown bit is a set bit that no db feature claims.
- Tile and tile-relative segbit: flow/gap_report.py, from tilegrid.json (baseaddr, word offset).
- Per-design evidence: build/gap/<name>/report.json and build/gap/<name>/viv/<name>.viv.fasm.

## XADC INIT registers (proposed segbits)
- Builds: designs/gap/xadc_fz_{none,all,0..8}. Register INIT_r bit b gets index j = (r - 0x40) * 16 + b, 0..511.
  - xadc_fz_k sets every (r, b) whose j has bit k set; xadc_fz_all sets all 512; xadc_fz_none sets none.
- Result (build/gap/xadc_segbits.json, from flow/gap_xadc_segbits.py):
  - xadc_fz_all: 515 unknown bits; xadc_fz_none: 3. The 512 differing bits are all in MONITOR_BOT_X46Y79.
  - Each xadc_fz_k has exactly 256 of them, as the code predicts. All 512 codes are distinct (0 collisions), so each bit maps to one (register, bit).
  - Independent check: designs/gap/xadc (INIT_40=0003, INIT_41=2000, INIT_42=0400, INIT_48=0100) has exactly the 5 predicted bits on top of the 3 base bits.
- The mapping is regular over all 512 entries: INIT_r[b] = frame (28 + b mod 2), bit (1696 + 8 * (r - 0x40) + b div 2). So frames 28 and 29, bits 1696..1951, 256 bits each.
- Not known: whether INIT_43..INIT_47 (documented as factory/test registers) should be exposed; whether Vivado ever writes values that differ from the INIT parameter (it did not in these builds).
- Not done: MONITOR_MID/MONITOR_TOP were not hit in these builds; the 35T has one XADC.

## DIFF_TERM
- IBUFDS #(.IOSTANDARD("LVDS_25"), .DIFF_TERM("TRUE")) on B11 (IOB_X0Y92, P) / A11 (IOB_X0Y91, N).
- The 6 bits sit in the bit range prjxray-db uses for IOB_Y0 DRIVE patterns. They are a subset of the existing LIOB33.IOB_Y0.LVDS_25.DRIVE.I_FIXED pattern.
- A plausible feature is LIOB33.IOB_Y0.LVDS_25.IN_DIFF_TERM (name is a guess). Only LIOB33 was observed; RIOB33 and other standards (TMDS_33 cannot take DIFF_TERM; SSTL/DIFF_* were not built) are untested.
- nextpnr-xilinx ce3f7c18 has no DIFF_TERM handling in fasm.cc. So an openXC7 IBUFDS has no on-die termination whatever the RTL says.

## DNA_PORT
- The 3 bits are next to the ICAPE2 bits in the same CFG_CENTER_MID segment.
- Vivado sets them whenever DNA_PORT is instantiated. openXC7 does not.
- Effect on silicon unknown (no board).

## FIFO
- The same 2 bits appear for FIFO18E1 (EN_SYN TRUE, EN_SYN FALSE) and FIFO36E1. They do not appear for any RAMB18E1/RAMB36E1 build.
- prjxray-db already has EN_SYN, FIRST_WORD_FALL_THROUGH, RAMB18_Y0.FIFO_MODE, ZALMOST_*_OFFSET. Those decode.

## Reproduce
```
python3 flow/gap_designs.py
pwsh vivado/run_gap.ps1 -Names xadc_fz_none,xadc_fz_all,... -Tag gap2 -Run   # Windows; DryRun is the default
python3 flow/gap_report.py --tag gap2 xadc_fz_none xadc_fz_all ...
python3 flow/gap_xadc_segbits.py
```
